# SKILL.md 渐进披露：把监控从第 6 步的长文里拆出来

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-06 |
| 输入 | 使用反馈：「SKILL.md 太长，8000+ token，监控部分在第 6 步，夹在几十条规则中间，容易漏看」 |
| 被评估对象 | `zoe-workflows`（`SKILL.md` / `references/` / `build.py`）；约束来源 `zoe-runtime/tests/contract/test_skill_cli_contract.py` |
| 方法 | 分节字符量实测 → 定位真正占体积的单元 → 对照契约测试确认搬运边界 → 改后跑 `build.py --check` 与 contract 测试 |
| 结论 | 「太长」成立，但**根因是第 6 步内部无层级 + 无体积闸门**，不是总量本身；做三层收窄，不做整体拆分 |
| 本文位置 | `zoe-workflows/docs/`（不在 `build.py` 的 `WHITELIST` 内，不进入发布包） |

## 0. 一句话

问题不是「文件长」，是**必然性规则与异常性规则混在同一层、且没有任何东西阻止它继续变长**。
所以修复分三件事：给第 6 步加层级并把异常分支分流到手册；把「漏看一次就误判」的纪律上提到
前三屏；把体积预算写进 `build.py --check`，让下一次膨胀变成红灯而不是靠人发现。

## 1. 实测（改前）

| 度量 | 值 |
|---|---|
| `SKILL.md` 总量 | 78,058 字符 / 982 行 |
| `### 先分流`（含全部 9 步） | 49,401 字符 = 全文 63% |
| 第 6 步「观察与监控」 | **24,063 字符 / 288 行** = 全文 31%，`##`–`###` 层级之间**零子标题** |
| 第 1–5 步 | 18,519 字符 |
| 第 7–9 步 | 5,980 字符 |
| `build.py check()` 的体积/结构断言 | **无** |

三个根因，按对「漏看」的贡献排序：

1. **第 6 步是扁平长文**：288 行里只有粗体段首与列表，宿主顺序读进来后没有任何可跳回的锚点；
   `--with-log` 语义、`empty_reason` 五分支、`watchd`、`[renewal]` 协约、四档汇报、`task logs`
   三条事实全部同级并列——必然性规则（每回合都用）与异常性规则（出事才用）混在一层。
2. **规则是散点，不是状态机**：30+ 条独立的「不要/必须」句散落在 525–812 行，缺少一个
   「当前状态 → 该做什么」的单一入口；漏一条就漏一个分支，且无法自检「我看全了吗」。
3. **无机械闸门**：v1.5.1 → v1.6 三轮迭代把第 6 步从几十行加到 288 行，没有任何一次红灯。

## 2. 改动

### 2.1 P0 结构收窄（纯结构，不改判据）

第 6 步切为 8 个 `####` 小节，每节一个判据主题：

| 小节 | 承接 | 改后字符 |
|---|---|---|
| 6.1 启动：游标按项目/目标集合隔离 | 双平台命令 + `--deadline-in` 反推 | 717 |
| 6.2 观测到 X → 动作 Y | **新增状态判定表**（10 行）+ 空返回是心跳 + 逐目标退出条件 | 1,356 |
| 6.3 退出码与 `[stop]` 分流 | 原退出码表 + 三条前提 | 1,014 |
| 6.4 续期单：让出必须带 `[renewal]` + `owner` | 待办队列 + owner 表 | 989 |
| 6.5 终态核对：`task status --refresh` 才是权威 | 终止判断 + `task report` + 空候选指引 | 298 |
| 6.6 动作线：`task logs` 只证明「动过」 | 三条事实 + 两条命令 + `empty_reason` 指引 | 626 |
| 6.7 汇报四档 | 四档表 + 过程观察进汇报不进结论 | 1,122 |
| 6.8 会话之外：只读守护 | `zoe-watchd.sh` 三条边界（细节入手册） | 228 |

第 6 步 24,063 → **7,260 字符**；`SKILL.md` 78,058 → **38,970 字符 / 880 行**。

6.2 的判定表是本节唯一的新增结构（不是新规则）：它把 6.3/6.5/6.6 里原本散落的判据按
「观测到的状态」重新索引，每行第三列写「为什么不能想当然」，对应历史上的真实误判。

### 2.2 P1 按需分流

新增 `references/monitoring-playbook.md`（11 节），承接**异常分支与低频语义**，原文措辞
整体搬移、不重写：`--with-log`（§1）、续期算法（§2）、`[tick]`/`--tick-content`（§3）、
digest 全量（§4）、`[stop]`/`--stop-file`/脚本内部要点（§5）、空候选（§6）、游标边界（§7）、
事件过滤（§8）、`task logs` 判读与 `empty_reason` 表（§9）、`zoe-watchd.sh`（§10）、
无脚本等价协议（§11）。

登记三处，避免「文件在但宿主不知道何时读」——这是本仓库记录过的失效模式：

- `build.py` 的 `REQUIRED_FILES`：缺文件即构建失败；
- `SKILL.md`「按需读取」：写明触发条件（监控异常 / 会话外观测 / 无 bash·jq）；
- 第 6 步导语：内联链接 + 每条小节末尾的就地指引（§N），不做集中目录。

### 2.3 铁律上提

`## 能力与边界` 之后新增 `## 铁律（Gate）`，8 条一行制，每条带判据位置：唯一写者、
受理≠派发≠运行、监控器退出≠完成、终态≠成功、Agent 自述≠证据、让出必留续期单、
空候选不写完成、成员不自验收。必读项由此离开长流程，进入前三屏。

### 2.4 P2 机械闸门

`build.py` 新增 `SIZE_BUDGET` / `STEP_BUDGET` / `SUBSECTION_BUDGET` /
`STEP6_MIN_SUBSECTIONS` 与 `size_problems()`，在 `check()` 中调用：

| 断言 | 阈值 | 改后实测 |
|---|---|---|
| `SKILL.md` 总量 | ≤ 46,000 字符 | 38,970 |
| 单个工作步骤（1.–9.） | ≤ 9,500 字符 | 最大 7,260（第 6 步） |
| 第 6 步每个 `####` 小节 | ≤ 2,500 字符 | 最大 1,356 |
| 第 6 步 `####` 数量 | ≥ 2（防退回扁平长文） | 8 |

`_step_spans()` 只在 `## 工作步骤` 与 `### 用任务组交付` 之间切分：组交付小节自带
`1. …` 编号列表，不截断会被解析成重复的 1–5 步（实测会产出 14 个「步骤」）。

闸门只卡 `SKILL.md` 与工作步骤，不给 `references/` 的历史欠账（`cli-contract.md` 55 KB）
一次性爆红——先止住出血点，再谈存量。

## 3. 不采纳

| 方案 | 裁定 | 依据 |
|---|---|---|
| 把 9 个工作步骤整体拆成 `references/workflow.md` | **不采纳** | 第 1–5、7–9 步合计 24.5k 字符，是全流程主动线；拆出去等于每次执行多一跳。问题集中在第 6 步，定点拆 |
| 把第 6 步命令搬进 `references/cli-contract.md` | **不采纳** | `test_skill_cli_contract.py:44` 只解析 `cli-contract.md` 的 ```text 块，`bash …` 行首 token 会被判成未知子命令（`2026-11-05-dispatch-retry…md:548` 已记录） |
| 删「纪律」句压缩体积 | **不采纳** | 这些是 v1.5.x 三轮修复的产物，删掉等于回退旧缺陷（预算到期当完成、`[log]` 当证据） |
| 拆分后把 `BANNED_CLAIMS` 一并扩到手册 | **本批不改 runtime 仓** | 该断言在 `zoe-runtime` 侧，跨仓改动应单独提；本批已自查手册不含 5 条禁用文案，将来扩扫不会红 |

| 检查 | 结果 |
|---|---|

| `ZOE_SKILL_DIR=… pytest tests/contract/test_skill_cli_contract.py` | 8 passed |

## 5. 判错条件

改动被视为失败，出现任一即回滚或重做：

- `SKILL.md` 总量超过 46,000 字符，或第 6 步重新出现一个 >2,500 字符的小节；
- 第 6 步的 `####` 小节数 < 2（说明又退回扁平长文）；
- 手册里的异常分支在 `SKILL.md` 找不到入口（无内联链接或链接失效）；
- 出现「监控器正常退出即完成」「日志静默即卡死」「`[log]` 即证据」这类表述；
- `--with-log` / `empty_reason` / `--stop-file` / watchd 的判据在两侧**同时**缺失。
